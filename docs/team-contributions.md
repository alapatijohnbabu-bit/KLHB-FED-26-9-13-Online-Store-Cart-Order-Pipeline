# Team Contributions and GitHub Workflow

The repository has three listed team members. Agree on the exact module allocation together and record changes here as work is assigned. Do not claim a contribution before it is made.

## Suggested allocation
- **Contributor A — product catalogue and data models:** product/customer models, sample data handling and catalogue search.
- **Contributor B — cart and inventory:** cart operations, quantity validation, stock checks and totals.
- **Contributor C — checkout, orders and reservations:** simulated payment, order status pipeline, cancellation and reservation rules.
- **Integration is shared:** agree who will coordinate integration and UI, while every member reviews and tests the whole project.

## Required contribution practice
1. Each member uses their own GitHub account; never share credentials.
2. Make small, meaningful commits throughout each phase.
3. Aim for at least one meaningful commit per team member per week.
4. Work on separate branches where practical; merge through pull requests or an agreed team process.
5. Commit only the files you actually worked on.
6. Tag phase deliverables such as `review-1`, `review-2` and `final`.
7. Keep this document aligned with the real allocation and commit history.
